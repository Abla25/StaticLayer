        Admin access & sign-in

        Password-less login with GitHub OAuth is built in and free — no Cloudflare Zero Trust plan, no credit card, and no password to remember after the first setup. Create a GitHub OAuth App once, set 4 Worker vars, and the login screen shows "Sign in with GitHub". Your admin password stays as a fallback and is never sent to GitHub.

        Lost the admin password? Once GitHub sign-in is configured, just click "Sign in with GitHub". Otherwise rotate it: npx wrangler secret put ADMIN_SECRET (you choose the new value) — or reinstall fresh. Re-running the installer preserves your existing secrets (including the current password) by design.

        Set up GitHub sign-in — step by step

        1. Open github.com → your avatar → Settings → Developer settings (bottom of the sidebar) → OAuth Apps → New OAuth App.
        2. Application name: anything, e.g. "StaticLayer admin".
        3. Homepage URL: …
        4. Authorization callback URL: … — this exact URL.
        5. Click Register application, then copy the Client ID shown on the page.
        6. Click Generate a new client secret, then copy the Client secret (shown only once).
        7. Find your GitHub numeric user id: open https://api.github.com/users/your-login — copy the "id" number (e.g. 1234567).
        8. Set the Worker vars: GITHUB_CLIENT_ID = the Client ID, GITHUB_ADMIN_IDS = your numeric id (or GITHUB_ADMIN_LOGINS = your login). Set GITHUB_CLIENT_SECRET as a secret: npx wrangler secret put GITHUB_CLIENT_SECRET (or in the dashboard: your Worker → Settings → Variables → Edit → add as a secret).
        9. Re-deploy (hosted installer or npx wrangler deploy), then refresh this page: the login shows "Sign in with GitHub". Only accounts in your allowlist can open the console.

        Privacy: GitHub sees only your login — the identity provider you chose. The token is used once to read your id and is then discarded, never stored. No visitor data ever leaves your Worker.

        Telegram alerts

        Get a private notification on Telegram when a new comment is awaiting moderation. Privacy-first: the message contains no comment content — only "a new comment awaits moderation" plus a link to this console. Your bot token and chat id are stored only in your own private D1 database.

        Create your bot: open Telegram → search @BotFather → /newbot → choose a name and a username → copy the token it sends you.

        Find your chat id: message your bot once (e.g. "hi"), then open https://api.telegram.org/bot<YOUR_TOKEN>/getUpdates in a browser and copy the number in "chat":{"id":123456789,…} (channels/groups have a leading minus).

        Then press Save settings and post a comment on your site: you'll get the notification.

        Polls

        Create StrawPoll-style polls for any page. Votes are anonymous (no IP, no cookies) and protected by proof-of-work; one vote per browser uses an anonymous in-browser token when enabled.

        New poll

        Leave empty for a global poll — shown on any page where you embed it. Set it to show the poll only on that article's page.

        One vote per browser — stores an anonymous token in the visitor's browser (no cookies, no personal data)
        Multi-select — visitors can pick several options and vote once for the whole set (single Proof-of-Work, one vote per option)
        Privacy & GDPR — read before enabling.
        • Enabling this makes the widget store a random, anonymous token in each visitor's browser (localStorage). It is not a cookie and contains no personal data; only a hash of it is kept in your own D1 — never sent to us.
        • It is nevertheless a persistent local identifier: the widget uses it to recognise "this browser already voted" across visits. Under GDPR that is a form of identification, so inform visitors in your privacy policy if you use it.
        • It does not guarantee "one person = one vote": a visitor can clear browser storage and vote again. It only raises the bar against casual double-voting.
        • You remain the data controller for your site; StaticLayer never receives, stores or sees the token.
